# 给指定好友发送私信

## 目标

在抖音网页端找到用户指定的好友，并原样发送指定消息，同时避免错发和重复发送。

## 所需输入

- `friend_name`：目标好友昵称或唯一识别信息
- `message`：消息正文，必须原样发送

任一输入缺失时先询问用户。

## 标准流程

### 1. 启动浏览器

1. 用户未明确要求使用本地浏览器时，调用 `browser_open`。
2. 保存返回的 session，并在后续所有 `browser_*` 调用中复用。
3. 打开抖音官网；如果浏览器已在其他页面，使用 `browser_goto` 导航至抖音。

### 2. 确认登录状态

1. 使用页面返回状态或 `browser_snapshot` 检查是否能看到消息、私信、头像等登录后入口。
2. 若出现登录二维码、手机号登录或其他未登录提示：
   - 告知用户需要在当前 managed browser 中完成登录；
   - 等待用户确认后再继续；
   - 不得切换到其他浏览器模式。

### 3. 进入消息页面

1. 点击“消息”或“私信”入口。
2. 页面跳转后获取新快照；如果操作打开了新标签页，先调用 `browser_tab(action="list")`，再选择新标签页。
3. 不要同时保留本次任务产生的重复抖音标签页。

### 4. 查找目标好友

按页面实际能力使用以下方式之一：

- 在私信会话搜索框中搜索 `friend_name`；
- 在已有会话列表中查找 `friend_name`；
- 若消息页没有会话搜索，可使用抖音站内搜索找到用户主页，再进入私信。

选择目标前必须核对：

- 昵称与 `friend_name` 一致；
- 如页面显示抖音号、头像、备注或其他身份信息，也应结合核对；
- 若出现多个同名用户且无法唯一判断，停止并询问用户，不得任选一个。

### 5. 发送前检查

1. 打开目标聊天窗口并重新确认窗口顶部昵称。
2. 定位消息输入框。
3. 将 `message` 原样填入，不增加引号、前缀、后缀、表情或换行。
4. 若页面已有一条内容完全相同、时间很近的本人消息，且本轮此前发生过发送超时或中断，则不要再次发送。

### 6. 执行发送

1. 优先使用页面明确的“发送”按钮；若页面约定 Enter 发送，也可调用 `browser_press(key="Enter")`。
2. 只执行一次发送动作。
3. 若发送调用正常返回，进入单次验证。
4. 若发送调用超时、报错或状态未知，进入“异常与防重复处理”，不得立刻重试。

### 7. 单次验证

发送后最多检查一次聊天窗口：

- 最新本人消息的文本与 `message` 完全一致；
- 消息位于目标好友会话中；
- 若页面提供时间或发送状态，可作为辅助证据。

满足以上条件即停止工具调用并报告成功。

## 异常与防重复处理

### 发送动作超时或中断

1. 重新获取目标聊天窗口状态，不执行发送。
2. 查看最新本人消息：
   - 存在完全相同的 `message`：判定已发送，不重试；
   - 明确不存在：可再执行一次发送，然后最多验证一次；
   - 页面无法加载或无法判断：报告“发送状态不确定”，请用户人工确认，不重复发送。

### 未找到好友

- 尝试会话搜索与站内用户搜索各一次；
- 仍未找到时报告结果，并请用户提供抖音号、主页链接或更准确的昵称。

### 登录失效

- 停止操作并请用户登录；
- 用户确认登录后，从“确认登录状态”继续；
- 不重复启动其他浏览器 session。

### 页面结构变化

- 调用 `browser_snapshot` 获取最新可访问结构；
- 使用可见文本、角色和最新 ref 操作，避免猜测旧 ref；
- 若关键入口不可识别，报告阻塞点，不通过脚本绕过页面限制。
