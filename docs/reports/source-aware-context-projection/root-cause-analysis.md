# Root cause

原`SessionHistory.context_turns()`从当前会话Pin表取所有非active原文，对整个轮次（包括JSON解码内容）做包含搜索；命中任何位置即排除整个user/assistant/tool协议组。触发条件不是文件删除或泄漏，而是请求临时历史投影中的信息省略，SQLite事实仍在。

1. 失效短句与独立用户要求同在一条消息时，整轮排除连带丢弃全部要求。公开L02的分页、排序、空状态在替换后损失3项来源；中文与相对路径在撤销后使累计损失达到5。
2. 单凭文本没有消息身份，无法区分重复句子、独立轮次或后来重新提出的要求；原内存Session及恢复视图未携带消息ID。
3. 原助手可能在其他轮次复述旧命名。原用户轮被去除不代表旧语义消失，助手复述也不能当成新用户确认。真实Live中部分信息经助手保留，但来源等级降低。

本轮从e9f2e822的Git archive提取原源码到全新临时目录，在新合成SQLite与SyntheticClient实际AgentLoop请求上重现3/累计5来源损失。修改后同样独立条件下损失0/0；没有读取原Live私有数据库、修改旧模型回复或改判历史结果。
