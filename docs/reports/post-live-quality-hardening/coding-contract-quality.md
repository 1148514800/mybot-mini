# Coding合同检查的实际实现

仅在现有CodingTaskController.instruction中增加紧凑通用合同提示：读任务与相关README，提取明确输入/输出/业务边界；按相关性选择正常、边界、异常情况；追踪真实业务入口；完成前比较已执行测试与合同，公开未验证要求。包含数值零/符号/舍入、空集合、类型、Unicode、序列化及输入不变等可选关注点，不强制每个普通任务跑全部类别。

没有增加第二个Agent、合同数据库、自动Judge或自测权限；没有在Harness里规定负零语义，没有泄漏旧T02独立断言。流程是提供给模型的指令，不是对模型一定遵循的硬保证。原Controller verified只绑定当前Revision的实际指定测试，不受模型声称或公开测试口头成功影响；python -c仍不能构成可信Revision测试证据。

五个新Fixture分别为仪表差值、成员列表、Unicode检索目录、容量类型、跨文件调度入口。真实AgentLoop+合成Client执行读取README→读取入口（跨文件场景再读helper）→报告未修复/未测试；断言确切合同与实际源码送入后续请求、相关通用指令存在、文件不变及无伪verified。独立原生命令/Receipt回归则验证真正修改→自测→Revision链路。合成Client预定行为只能证明信息传递与安全边界，不能证明真实模型的边界检测率提高。
