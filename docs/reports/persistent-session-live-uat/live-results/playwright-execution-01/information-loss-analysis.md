# Live information loss

依据本次真实SDK观察metadata与真实回复独立核对，不复用离线3/5作为结果。原SQLite历史没有删除；损失发生在向模型构造历史投影时。Pin语义撤销不等于从所有历史文本中删除词语。

|时点|被移除完整轮/消息|原用户无关信息来源损失|真实保留语义|
|---|---|---|---|
|替换后请求12（第三轮）|1轮/2消息|3项：每页20条、按相对路径排序、空目录空状态|请求11助手回复复述了这3项，该助手消息仍在请求12|
|撤销后请求13（第四轮）|累计2轮/4消息|累计5项：再加仅中文、条目显示相对路径|请求12助手回复复述了后2项，该消息仍在请求13；旧3项没有出现在这个保留回复中|

独立hash比对证明上述助手消息确实保留在实际SDK请求，不仅是UI上可见。证据见information-loss-evidence.json的retained_assistant_proofs；hash算法与冻结observer一致（sort_keys JSON，ensure_ascii=False）。因此3/5是原user来源单元损失，不是3/5事实都彻底消失，更不是物理遗忘证明。助手复述继续发挥影响，却不能代替原用户来源与授权，这是产品完整性问题。

额外人工检查：第一轮助手曾提出排序大小写、分页可配置、空状态文案三项开放问题，第二轮保留回复未再次承载这些问题；替换整轮时也失去这一组助手建议上下文。它们不是冻结的用户独立单元，不混入3/5数量。L01最终总结也未逐项重述根目录/符号链接/.md筛选等未固定细节，不能把核心Pin成功说成无损长记忆。

L01从第四轮开始确定性压缩，末轮只保留1个完整历史轮、5轮被摘要/省略；L03同样1/5。摘要是本地确定性处理，模型摘要请求0。上下文确实不完整，但两Pin均未省略；所有finish_reason=stop，当前输入未裁剪，输出未截断。上下文估计上限14000与输出保留1800保持冻结值，供应商真实窗口未知。
