# Provider failover and accounting

RuntimeAccounting.dispatch在一次物理记录和PHYSICAL上下文中完成SDK创建及流消费。logical_requests按Agent调用计，physical_requests按真实准入的Provider尝试计，HTTP事件钩子单独计发送尝试；SDK max_retries保持0。物理准入与HTTP钩子发布实时资源快照，运行中不会用请求前旧快照冒充0次；额外快照不增加物理记录。创建迭代器和消费迭代器不是两次请求。

主要Provider首个数据块之前出现原策略允许的连接、超时或可恢复HTTP错误，可以经原备用Token/Controller预算切换。PROGRESS在收到任何Chunk时即置位，包括仅role、空数据/Usage或工具片段；之后不透明切换、不拼接备用输出。尤其Primary半程超时也检查该标记，不能因异常在消费外层产生就误Fallback。

分别记录streaming_requested、streaming消费已开始、first_chunk_received、output_exposed、terminal_trusted、stream_status及HTTP尝试。流中错误保留部分预览及明确失败；Primary与Backup各自占一个物理请求。没有Usage返回unknown/null，快照可显示已知subtotal但不冒充完整供应商总量。

最终浏览器轮8次SDK MockTransport HTTP，绝非真实供应商8次；所有真实Provider发送为0。SDK专项验证一逻辑请求、两物理Provider尝试的首Chunk前Fallback，以及任何Chunk之后零备用尝试。原非流式Failover断言保留。
