# Security and source integrity

No production mybot/, provider SDK, Patch, Controller, authority, approval, Cookie/CSRF/CSP, native journal or evaluation sandbox code changed. New code is confined to C02 scripts/tests and current documentation. C01 source/results, old canary/historical grades/HALT/ledger/remaining allowance, Phase25 history, main, Tags/ZIP, user projects, user Chrome/8765 and shared AppleDouble object sidecars were not modified. No historical private SQLite was opened.

All coding workspaces are newly owned disposable Git repositories without remotes. Candidate writes only through native Preview/Receipt Patch to the two exact allowed paths. Public tests, README, __init__, .gitignore, complete Git Index/metadata and unknown files are protected. Per-revision actual deltas/whole maps and cumulative Journal prove attribution. Unknown external drift is preserved and HALTed, never reset or repaired. Negative publication/Stop tests retain actual state and do not assert a fictional rollback.

Existing verified Seatbelt runner executes only the registered test command after one native approval, with bounded timeout/output and no host import of candidate. Hidden suites are trusted frozen bytes copied to separate post-turn grading processes; no results returned to model. In the synthetic environment only MockTransport is constructed, with dummy credentials and invalid mock origin; no real SDK endpoint is invoked.

Headed Chrome uses fresh verified0700 nonsymlink profiles, sandbox enabled and initially empty Cookie Jar; dual-origin-isolation probe uses only test markers. Own service/profile lifecycle helpers are reused unchanged, with actual exit0/SDK close/SQLite/Lease/port cleanup. No original browser Cookie was read/copied/deleted; no 8765 page opened. Private operator diagnostics remain outside Git.

Reports publish only bounded redacted native metadata/hashes/counts and masked screenshots. No full requests/replies/chunks, key/base URL, raw tool arguments, Receipt/approval nonce, Cookie/CSRF, private database/profile, raw logs or candidate source are committed. All tracked/new report files are checked against locally configured credential values without printing those values; filenames/artifact types and changed paths are audited separately. Freeze stores configuration byte fingerprints and exact original local path privately; no new credential file is created.

The first broad validation run overlapped a pre-freeze test-harness review and is not the final source-stable validation evidence. The final run records identical before/after Python/dependency hashes and a deduplicated inventory. Only final-source results count for offline acceptance. Fault-injection test uncertainty is expected negative evidence, not an unexplained operator side effect or a successful Live result.
