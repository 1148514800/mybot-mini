# 剩余风险与产品限制

- 无 OS 沙箱的 legacy_confirm/host_confirm 和第三方 MCP 仍有独立副作用边界；默认文件只读不代表整个进程只读。宿主 Python 注册代码是信任根，不防恶意本地插件。
- 原 Patch 仍不是跨文件崩溃原子事务，也不是文件系统 compare-and-swap；恶意并发的所有竞争窗口没有解决。有限竞争场景实测拒绝，不外推为完整并发防护。
- 精确原文引用只证明文本存在，不保证语义提取完整、命令/反例分类正确；文档内容也是不可信任务数据。模型可遗漏整条要求，故 Task Correctness 始终 unknown。
- Level2 的 requirement→test 关联是模型提议，宿主只确认测试真实且当前，无法自动证明覆盖；没有生产独立 Oracle。模型自主写测试仍可能遗漏或修改验收意图。
- 合同有输入/累计预算，新增工具 Schema 和工具往返可能消耗更多 Token/请求；没有真实模型费用或质量验证。预算耗尽不会自动续跑。
- 当前每轮是新任务，不实现跨轮需求替代记录或跨会话永久合同；旧合同只保留原 Session 文字，不能恢复权限。Web 内存重启丢失。
- Web 需求原文简述仅从页面已脱敏的用户消息坐标恢复；发生脱敏长度变化时仅显示编号。项目文档条目目前仅编号/分类，完整引用需要原工具/源码检查。
- Legacy 完整审批上限与路径/空文件/父目录限制（原生协议也未提供空锚点插入）使部分旧调用有意不兼容；无法展示即拒绝，不承诺自动迁移任意旧脚本。
- 真实模型、DeepSeek、GLM、真实语义摘要、付费 Judge 均0；旧Live结论不改，本轮 OFFLINE PASS 不证明实际 Coding Task Success 提升。
