# Decision Provenance v1

入口：`DecisionProvenance.statement(message_id, span, quote)`只读校验同Session、user角色、完整未脱敏消息和Python Unicode码点跨度，要求quote逐字一致。返回user_statement、semantic_classification=unclassified，无确认事件。它证明“用户曾这样说”，不自动决定这句话是强制要求、可选方案或未决事项。

`DecisionProvenance.view`经DecisionTimeline读取真实pin.added确认事件；每项保留session_id、source_message_id、source_span、source_role、original_quote、confirmation_event_id、confirmation_event_sequence和current_lifecycle_status。源校验通过才为host_confirmed_pin/source_verified=true；来源损坏、截断或脱敏时保留审计元数据，quote为空、unverified_pin_record，不能进入模型的有效Pin集合。

分类词汇明确区分user_statement、host_confirmed_pin、user_optional_proposal、user_unresolved_question、assistant_suggestion、assistant_unconfirmed_inference。classification_proposal只产生不持久化、verified=false/user_confirmed=false的提议，拒绝自称host_confirmed_pin；它不是工具、确认API或语义分类器。普通用户的可选/未决表达不会被关键词自动升级。用户明确选择open_question等原有Pin分类只确认原文和用途，不自动验证其改写。

可信视图不读取助手文本、TaskContract、测试结果、Receipt或Controller。工具注册表不新增确认工具。模型不能通过普通回复或Tool Call产生确认事件。原有用户Pin创建、替换、撤销入口和真实确认动作保持；新模块无写入口。

items是带来源验证标志的有界生命周期审计集合，status_at_boundary与current_lifecycle_status分别表达历史查询状态与最终状态；判断当前可信Pin必须同时要求source_verified=true和status_at_boundary=active。不得把失效或来源不完整的审计项当成当前决定。
