# Web体验观察

可用部分：实际浏览器完成新建、输入发送、同会话三轮、独立空会话切换、展开真实工具卡片，回复/代码排版可读；状态、最终Usage、物理/HTTP数量与账本一致。两个失败Coding任务显示失败/blocked、revision0，没有误报verified。U06明确显示语义未应用和规则回退，窗口未知与估算/已报告Token分开。

主要问题：

- Patch失败的可行动诊断不足。安全类别粗化或为空，卡片仅“Patch未确认成功提交”；主回复也没有具体停止原因。U04更深层只读检查才找到属组不匹配。
- 普通读取卡片展开仍只有“调用已完成”，缺少已读文件路径/范围等适当白名单信息，用户难以追踪13次工具究竟读了什么。不要因此暴露原始参数或有效能力。
- 等模型期间资源面板可能仍显示0次；调用数通常在响应/资源快照后才更新。当前非Token流，首次正文与完整回复同时出现；不是把已知非流式当Bug，但计数标签的时间语义可以更清晰。
- Markdown嵌套清单呈现较扁平，长回复与长用户需求需滚动；本轮没有专门重新验证手机端，不能声称移动端体验通过。
- U06用户要求80字确认，真实模型仍多次长回复；U02最终清单过度扩张，不应由“排版清楚”掩盖指令问题。

实测完整回复后端延迟与每次SDK耗时见resource-usage.json；未独立测浏览器首个字符渲染时间，首Token延迟保持null。无真实审批窗口到达，浏览器审批交互本轮未验证。
