## F01：UAT Fixture元数据兼容性漏检（P1，测试工程缺口；产品安全拒绝合理）

U04文件继承/tmp父目录gid0，服务egid20。原ApplyPatch.check_metadata要求uid与gid均相同；原生只读检查返回unsupported_ownership，Web归类metadata_changed。Preview之前就阻止，无写入。UAT新增13项自测验证oracle、预算、生命周期和合成触发，但未实际以原Patch预检检查Live Fixture元数据，导致这个能力前提在冻结前未发现。必须承认是本轮预检缺口，不把它包装成纯产品Bug或模型能力失败。U05同属组风险存在，但本次失败类别未知，不能直接归因。后续应在新验收批次冻结前完整检验Fixture支持边界；本轮禁止修复和补测。

## F02：Patch停止原因无法从Web充分诊断（P1，已观察到的产品UX/观测缺陷）

U04仅显示metadata_changed，没有展示unsupported_ownership及当前允许的元数据边界；U05只显示“Patch未确认成功提交”，具体类别null。两个主回复都被概括成0修改/0有效测试，用户无法知道如何行动。安全停止正确，但非敏感错误码与根因链可被更精确地展示。本UAT观察层没有保留实际工具参数/原始错误文本，这也限制了U05归因；不能靠推测补全证据。

## F03：真实语义压缩付费后未应用（P1，当前配置下确认；不外推所有配置）
